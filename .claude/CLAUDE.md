# Jobe - Career Intelligence Skill

Full-pipeline job search automation: discover, evaluate, apply, track, follow up, interview prep, analyze.

## Commands
```
/jobe find                          Discover recent jobs (30-day filter + liveness check) + auto-generate resumes
/jobe [URL]                         Evaluate posting with A-G blocks, generate resume + cover letter
/jobe [company] [role]              Same, finds the posting first
/jobe apply [slug]                  Fill + submit one application via Camoufox stealth automation (default); glance before submit + email-confirm loop
/jobe apply-all                     Process entire apply queue via Camoufox stealth auto-apply (default; headless); --top N, --paste fallback, --headful, --warm/--no-warm
/jobe apply-assisted                Fallback: paste-ready blocks (login-walled forms / --paste)
/jobe batch url1 url2 ...           Evaluate multiple postings
/jobe tracker                       View pipeline + stats + conversion rates + orphan check
/jobe interview-prep [company]      STAR+R story mapping + likely questions
/jobe followup                      Follow-up cadence + message drafting
/jobe patterns                      Application history analytics
/jobe contacto [company]            LinkedIn outreach (4 contact types, 300 char)
/jobe deep [company]                6-axis company research
/jobe project [path]                Portfolio project evaluation
/jobe linkedin-tab                  Ingest YOUR open LinkedIn Jobs tab (read-only via Chrome ext)
/jobe linkedin-search               Drive YOUR logged-in LinkedIn search + paginate (opt-in, user-present via Chrome ext); also find --linkedin
```

## Architecture
- `SKILL.md` is a thin router (~76 lines). Reads `modes/_shared.md` + `modes/_profile.md` + the appropriate mode file.
- 20 mode files in `modes/` (18 workflow modes + 2 shared context files; `linkedin-tab` reads the user's open LinkedIn Jobs tab, `linkedin-search` drives the user's logged-in LinkedIn search)
- 4 agents: jd-analyzer, company-intel, competitor, job-discovery
- `lib/` modules: config (env loader with repo + `~/.jobe` fallback), tracker, normalize (ATS chars), sync-check, archetypes, patterns, snapshot, **posting (canonical Posting schema + parsers)**, **minhash (MinHash + LSH, pure JS)**, **dedup (URL exact + dedupKey + MinHash LSH fuzzy)**, **rrf (Reciprocal Rank Fusion k=60)**, **role-queries (derives role search terms + a title matcher from the user's seeds; shared by every source and by rank)**, **rank (profile-driven: title gate + fullScore from the user's target-role tokens + bullet-library keywords; permissive when unconfigured; RRF fusion of profile-overlap/seniority/freshness)**, **enrich (JD fetch + 30-day cache, with extractors for Greenhouse / Lever / Ashby / Workday / SmartRecruiters)**, **ghost-score (multi-signal: age, repost, company-ratio, layoff, title-fuzz)**, **calibration (LLM-judge + human, Cohen's kappa)**, **bias-audit (name/school perturbation)**, **tailoring (generic/light/deep depth tracking)**, **bullet-select (per-JD bullet selection from `data/bullet-library.json` filtered by archetype, scored by JD-keyword overlap, returning experience[] + selectedProjects[] ready for resume JSON)**, **slug-harvest (role-less Brave queries that enumerate unknown ATS slugs into the index before each run, making the seed list vestigial)**, **agent-import (merges WebSearch-agent fallback discoveries into the pipeline output: extracts ATS slugs into `data/companies/index.json`, normalizes, filters, enriches, fullScores, dedups, updates in place)**, **tracker-writer (atomic-write tracker.md + apply-queue.json mutations, plus `moveReportFolder` helper for `reports/{slug}` -> `reports/{applied|skipped}/{slug}` relocation)**, **tailor (JD-grounded tailoring: analyzeJD + rankEvidence + tailorBrief — the deterministic half of the reframe-to-JD step the generator runs; plus `auditResume(resume, jdText?, opts?)`, an advisory resume-quality gate that hard-checks required sections [education/experience/contact — generic presence, no field specifics], bands metric density 0.8-2.5, flags AI-tell tokens / uniform openers / wall bullets, runs a JD-vocabulary coverage check when `jdText` is passed, and a page-authoritative 2-page fill gate when `opts.pageMetrics` is supplied; and `auditProse(text)`, an advisory-only AI-register linter for cover letters / summaries / free-text answers — never a gate, never an authorship verdict)**, **linkedin (logged-in LinkedIn search helpers: buildSearchUrl with Remote + Past-week + US filters, profileQueries, parseSearchCards to turn a Chrome-extension read_page accessibility dump into postings; powers `modes/linkedin-search.md` — the codifiable half; the browser drive is agent-orchestrated)**
- `lib/apply/` modules (the Camoufox auto-apply harness): **camoufox (stealth-Firefox launcher via camoufox-js, viewport:null; `userDataDir` opt builds a PERSISTENT profile via `launchPersistentContext` for the Ashby reCAPTCHA-v3 warm mode)**, **answers (build the flat answer map from a report's resume JSON + optional `data/apply-profile.json`; identity from the resume, work-auth/EEO from the apply-profile, EEO declines by default; uploads the NEWEST PDF resume as PRIMARY with DOCX fallback; reads an optional `apply-profile.postalCode` for required ZIP fields)**, **filler (label-first scan/fill across Greenhouse/Lever/Ashby; react-select comboboxes; resume upload LAST to survive ATS autofill re-renders; custom free-text questions detected, never invented; `opts.slow` slows typing cadence for Ashby warm mode)**, **url-normalize (canonical ATS posting URL; generically rewrites Greenhouse board pages `job-boards.greenhouse.io/{board}/jobs/{id}` and any `gh_jid` careers wrapper to the fillable `/embed/job_app` form via `deriveBoardToken` — no per-company entry needed)**
- **Multi-user workspace resolution** lives in `lib/config.js`, which owns the SYSTEM/USER split: `getSystemRoot()` returns the shared install root (code, `configs/`, and field-neutral seeds `data/companies/non-tech-seed.json` + `data/companies/staffing-list.json`); `getUserRoot()` / `getProjectRoot()` return the ACTIVE user workspace under `users/<slug>/` (profile, reference, `data/**`, `reports/`, `signals/`, and that user's own company index). The active user is resolved `JOBE_USER` env var > `users/.active` pointer file > install root (single-user back-compat). `scripts/user.js` manages workspaces (`list` | `current` | `new` | `use` | `migrate`).
- `scripts/camoufox-apply.js` - the auto-apply harness (default apply path). Runs HEADLESS by default (cleaner under Camoufox — a real display leaks signals that conflict with the spoofed fingerprint); `--headful` only to watch a run or clear a wall. One long-lived process per job holds the browser open across the glance + email-confirm; the agent drives it via `signals/apply/{slug}/{state,control}.json` (`run <slug>` / `confirm <url>`). Ashby boards auto-enable **warm mode** (`--warm` / `--no-warm` override): a persistent fingerprinted profile under `signals/apply/_profiles/{ats}` (gitignored) + a Google warm-up visit + slow human-cadence typing + pre-submit dwell to survive Ashby's invisible reCAPTCHA-v3 spam score; a lock enforces ONE Ashby run at a time (a second concurrent Ashby run bails to `needs-manual`)
- `collectors/pipeline.js` orchestrates the unified discovery pipeline. Phase 0 = slug-harvest, phase 1 = parallel sources, phase 2 = filter (incl. a cross-run history drop of any posting whose company+role `dedupKey` was already applied to or skipped in `data/apply-queue.json`, counted as `applied/skipped=N` in the after-filter log; override with `--include-applied`) + enrich (top 300) + score, phase 3 = persist + write `discovery-summary.json` with `needsAgentFallback` boolean
- `collectors/sources/` is a source-plugin registry. Each plugin exports `{id, name, requires, rateLimit, discover(ctx) -> Posting[]}`:
  - `aggregators/` - **Brave Search (recommended free path: 2K queries/mo, set `BRAVE_API_KEY`)**, SerpAPI Google Jobs, SerpAPI site: search, HN Who-is-hiring, **Remotive / RemoteOK / WeWorkRemotely / Himalayas (key-free remote boards)**, **linkedin-guest (public logged-out endpoint, no account automation)**, **Adzuna (ADZUNA_APP_ID/KEY)**, **JSearch (JSEARCH_API_KEY)**. Brave + SerpAPI use a per-(domain x role) query fan-out (~80 queries / run) instead of a single OR-megaquery, so specialty roles surface instead of being drowned under common terms
  - `company-specific/` - Amazon (public JSON), Apple (SSR scrape)
  - `ats-directories/` - Ashby customer boards
  - `ats-direct/` - Greenhouse, Lever, **Workday (multi-tenant)**, **SmartRecruiters (multi-company)**, **iCIMS (best-effort HTML scrape)**
- `collectors/ingest-manual.js` - human-in-the-loop ingest feeding the `linkedin-tab` + `linkedin-search` modes: reads the user's OWN open LinkedIn Jobs tab via the Chrome extension (read-only), or with `--from-accessibility` parses a Chrome-extension `read_page` (filter:"all") dump of a LinkedIn search page directly via `lib/linkedin.parseSearchCards`. Drops staffing-list + negative-list companies before role-matching (summary line reports the dropped count). The logged-in session is never automated unattended.
- `data/queries/seeds.json` - seed queries driving discovery (role + location pairs; covers tech + finance + pharma + retail + CPG + media + auto + telecom + energy + healthcare + insurance + defense)
- `data/companies/index.json` - emergent company index, auto-grown from every run + slug-harvest phase
- `data/companies/negative-list.json` - slugs to exclude
- `data/companies/staffing-list.json` - 33 staffing agency / recruiter / AI-data-labeling marketplace slugs dropped from discovery (they dominate LinkedIn deep-search pages as "Promoted" noise); applied by `ingest-manual` as a union with negative-list
- `data/companies/non-tech-seed.json` - verified Workday tenants + SmartRecruiters companies + iCIMS hosts for non-tech industry coverage
- `data/resume-baseline.json` - canonical resume structure (your own experience entries)
- `data/bullet-library.json` - per-role bullet pool with optional top-level `companyKeyMap`; each bullet tagged with `archetypes[]` and `keywords[]` for per-JD selection via `lib/bullet-select.js`
- `signals/discovered/{date}/` - per-run raw, merged, ranked, enriched, **discovery-summary** outputs
- `signals/cache/jd/` - 30-day JD cache (sha1-keyed)
- `scripts/` renders DOCX resumes + cover letters with ATS normalization, plus `bulk-resume-from-list.js` for fast triage runs over many URLs. `render-docx.js` lays out Summary -> Selected Projects -> Experience -> Skills -> Education -> Awards (projects BEFORE experience), honors an optional per-resume `projectsHeading` and per-experience-entry `pageBreakBefore`, uses `keepNext` to prevent orphaned section/job headers, and prints a `[resume-audit]` line (words/summary/projects/density) + a `[prose-advisory]` on the summary. `render-cover-letter.js` prints `[prose-advisory]` on the letter and parses `YYYY-MM-DD` dates at local noon (fixes a negative-UTC-offset off-by-one). `render-pdf.js` emits a text-based (selectable) PDF
- `data/` tracker, story-bank, followups, apply-queue
- `reports/applied/{slug}/`, `reports/skipped/{slug}/`, and `reports/needs-manual/{slug}/` per-job output (relocated by `moveReportFolder(slug, bucket)` after apply, skip, or when the resume is built but the ATS blocks automated submit)

## Key Design Decisions
- **Auto-apply default = Camoufox stealth, not Chrome (hard)**: `/jobe apply*` drives `scripts/camoufox-apply.js` (patched Firefox via camoufox-js). Chrome-over-CDP leaks `navigator.webdriver` + DevTools traces that trip automation-detection + email-confirmation walls — it was the detectable thing. Camoufox patches Firefox at the C++ level + humanize + geoip. Flow: auto-fill → glance (screenshot + summary) → submit → Gmail-MCP email-confirm loop → record. The agent orchestrates via `signals/apply/{slug}/{state,control}.json` (the Node harness and the Gmail MCP can't call each other directly). The old `--chrome` (Claude-in-Chrome) path is deprecated; `--paste` (paste-ready) is the login-wall fallback. Free-text answers are agent-written from real evidence (filler returns `questions[]`, never invents); answers are typed raw, so they must be ATS-clean (no `< > [ ] { } " \`). EEO/demographics decline by default — a user opts in via `data/apply-profile.json`. Runs HEADLESS by default (headful can *trigger* the security/spam checks headless avoids); `--headful` only to watch a run or clear a wall. Ashby boards auto-enable a persistent-profile reCAPTCHA-v3 **warm mode** (`--warm`/`--no-warm`), run ONE at a time, and never retry a `submit-blocked-spam` tenant. `url-normalize` rewrites Greenhouse board/`gh_jid`-wrapper pages to the fillable `/embed/job_app` form generically. Account-safety rule is hard: never automate the user's logged-in LinkedIn session — Camoufox uses a fresh fingerprinted session.
- **Multi-user workspaces (one machine, many people).** `lib/config.js` splits a shared SYSTEM layer (code, `configs/`, field-neutral ATS seeds installed once at `~/.jobe`) from a per-user WORKSPACE layer (`users/<slug>/`: profile, reference, `data/**`, `reports/`, `signals/`, per-user company index) so people targeting different fields never see each other's profile, evidence, queue, or reports. The active user resolves `JOBE_USER` > `users/.active` > install root, and `scripts/user.js` (`list`/`current`/`new`/`use`/`migrate`) drives it. With no workspace configured the active root IS the install root, so existing single-user installs are unchanged.
- Modes beat a long prompt: 20 files vs one monolith
- A-G block evaluation with ghost job detection (Block G)
- Archetypes are optional + user-defined (`configs/archetypes.json`); default is `General` (rank evidence by JD-keyword overlap). No field-specific archetypes ship.
- Positioning reasoning internal only, never in output
- ATS normalization in both render-docx.js AND render-cover-letter.js
- Recency: ATS collectors extract and filter by date fields (createdAt/publishedAt/updatedAt). WebSearch uses after: operator. Dead URLs filtered.
- **Discovery is query-driven, not company-driven.** The pipeline asks "what jobs in the market match the candidate?" not "what is new at this fixed watchlist?". The company whitelist (portals.json) is now a seed for the emergent company index (data/companies/index.json), not the primary source of truth.
- **Source plugin contract**: every file under collectors/sources/ exports `{id, name, requires, rateLimit, discover(ctx)}`. Missing env vars (listed in `requires`) cause the source to return `[]`; pipeline continues with remaining sources.
- **Dedup is downstream, not upstream.** Every source emits raw Posting[]; canonical schema in lib/posting.js normalizes, lib/dedup.js merges URL-exact then fuzzy on (company-slug, role-normalized, location-primary) sha1.
- **Enrichment is broad, scoring is JD-driven.** Top-K (default 300, was 60) gate-passing postings get JD text fetched + comp extracted + 30-day cached. The title gate + fullScore are profile-driven: postings are matched and scored against the user's target-role tokens (`data/queries/seeds.json`) and bullet-library keywords, permissive when unconfigured — no hardcoded role vocabulary. The pre-enrich quickScore only sets enrichment priority (seniority + freshness + ATS-canonical-URL boost).
- **Slug-harvest before discovery.** Phase 0 issues 21 role-less Brave queries (`site:boards.greenhouse.io after:DATE`, etc.) to enumerate unknown ATS slugs into `data/companies/index.json` before the parallel source loop runs. Direct-ATS plugins re-read the index at discover-time, so the same run reaps the new slugs. Over time the seed list becomes irrelevant — the index becomes the source of truth.
- **Bullet selection per JD (required for resume generation).** `lib/bullet-select.js` `buildExperience(baseline, spec)` + `pickProjects(spec, n)` score `data/bullet-library.json` bullets by JD fit and return ordered bullet/project arrays. Selection now weights JD-requirement terms (from `lib/tailor.analyzeJD`) ABOVE generic keyword overlap and treats archetype match as a BONUS (+1.5) rather than a hard gate — a requirement-relevant bullet can no longer rotate out of exactly the JDs that name it. Bullets sharing an optional `studyGroup` tag are near-duplicates (one selected per resume); `selectedProjects` dedup by an optional `name` display field (preferred over the id-derived label). Reordering a fixed bullet pool produces resumes that share identical body content across postings (only summary + cover letter differ); per-JD selection produces real differentiation.
- **WebSearch agent fallback.** When `discovery-summary.json.needsAgentFallback` is true (Brave returned <100 OR merged set <300), the find mode launches the `jobe-job-discovery` agent which uses Claude Code's WebSearch tool (no API quota) to targetedly hunt slugs the search APIs missed. The agent writes `signals/discovered/{date}/agent-discovered.json`; `lib/agent-import.js` extracts slugs into the index, normalizes + filters + enriches + scores, and merges into `ranked-enriched.json`.
- **Cross-run history filter (never re-surface applied/skipped).** `collectors/pipeline.js` drops any discovered posting whose company+role `dedupKey` matches a req already applied to or skipped in `data/apply-queue.json`. This keys on company+role (NOT URL), so it catches the same job re-discovered from a different source. Counted as `applied/skipped=N` in the after-filter log; override with `--include-applied`.
- **Resume-quality gate is advisory, never fatal.** `lib/tailor.auditResume(resume, jdText?, opts?)` hard-checks required sections (education/experience/contact — generic presence, no field/degree specifics), bands metric density to 0.8-2.5 (over-quantification is an AI tell), flags AI-tell tokens / uniform openers / 100%-metric-saturation / wall bullets (>65 words), runs a JD-vocabulary coverage check when `jdText` is passed, and a page-authoritative 2-page fill gate when `opts.pageMetrics {pages, lastPageFill}` is supplied. `auditProse(text)` is a separate advisory AI-register linter for prose fields — it flags a versioned set of AI-register flourish words + connector density, NEVER gates, and NEVER emits an authorship verdict (document-level AI detection is unreliable). Callers warn, never throw.
- **Resume rendering: projects-first, 2-page fill.** `render-docx.js` renders Selected Projects BEFORE Experience and uses `keepNext` + optional `pageBreakBefore` to avoid orphaned headers; the fill gate targets a full 2-page recruiter standard. `render-cover-letter.js` parses `YYYY-MM-DD` at local noon to avoid a negative-UTC-offset off-by-one; `render-pdf.js` emits a selectable text-based PDF.
- **Logged-in LinkedIn search sweep (`modes/linkedin-search.md`, `/jobe find --linkedin`).** The logged-out guest source returns thin, mostly-onsite listings that die in the remote filter; the logged-in search returns the personalized + promoted inventory from real companies. Reaching it needs the Chrome extension driving the authenticated tab (a headless source plugin cannot), so the drive is agent-orchestrated (the mode) and the codifiable parts (URL build, accessibility parse, staffing filter) live in `lib/linkedin.js`. Account-safety is hard: opt-in + user-present, human-paced, never unattended/headless/cron, never solve a visible CAPTCHA (the always-present invisible reCAPTCHA node in the DOM is normal and non-blocking — ignore it). `Past week` filter satisfies recency.
- **Folder lifecycle adds a third bucket.** `lib/tracker-writer.moveReportFolder(slug, bucket)` accepts `applied` | `skipped` | `needs-manual` (`reports/needs-manual/{slug}` for applications whose resume is built but whose ATS blocks automated submit), rewriting the queue entry's `resumeDocx` + `coverLetterDocx` paths and the tracker `reportDir` atomically.
- **Cover letter quality bar.** Every cover letter must contain (1) a specific dollar amount or measurable business outcome, (2) one leadership / scope signal, (3) one decision-grade outcome. The `_shared.md` Cover Letter section enforces this. Bulk-resume helper (`scripts/bulk-resume-from-list.js`) ships resume DOCX with `coverLetter` blank for follow-up composition.
- **Empirical backing (citations in lib/ modules):**
  - MinHash LSH fuzzy dedup (lib/minhash.js, lib/dedup.js): LSHBloom arXiv 2411.04257 (2024); datasketch defaults (128 perms, 18x7 bands, Jaccard >= 0.70 with bigram shingles).
  - RRF hybrid-ranking k=60 (lib/rrf.js, lib/rank.js): Bruch et al ACM TOIS 2024; +1.4% nDCG over dense, +18% over BM25 on BEIR/MS MARCO.
  - Multi-signal ghost detection (lib/ghost-score.js): Clarify Capital 2024 (n=1,200), Revelio Labs 2024, Hunter Ng arXiv 2410.21771.
  - Seniority-aware recency (+15 days for senior/staff in pipeline.js): Review of Accounting Studies 2023 on high-skill vacancy duration.
  - LLM-judge calibration (lib/calibration.js, Cohen's kappa >= 0.75 flag): arXiv 2506.13639 (2025).
  - Bias-audit (lib/bias-audit.js, name/school perturbations): Bertrand & Mullainathan AER 2004, Brookings 2024.
  - Referral-first pipeline ordering (modes/find.md): Burks et al QJE 2015 + Friebel et al NBER 2019 (field experiment).
  - Tailoring-depth tracking (lib/tailoring.js): Resume2Vec MDPI 2024 (+15.85% nDCG) as the strongest available anchor; tracking in tracker verifies the prior.
- **Unsourced numeric claims removed** from `_shared.md` ATS Format Rules (old "8.2% interview rate", "2.5x callbacks", "40% more callbacks" had no traceable methodology).
- Content differentiation: cover letter, "Why X?", and custom questions use different evidence. Rules in both evaluate.md and apply-assisted.md.
- Gate-pass scoring before resume generation
- Anti-fabrication: every claim traces to code. No internal project names.
- Deep technical bullets: algorithms, parameter values, architectural patterns
- Data contract: user-layer never overwritten. System-layer replaced on install. default.json protected with if-not-exists guard.
- install scripts copy CLAUDE.md, all 32 lib files (28 `lib/*.js` + 4 `lib/apply/*.js`, including `lib/config.js` + `lib/linkedin.js`), all modes, all agents
